1What this scaffold gives you

You write plain text. The build turns it into a funder-compliant PDF and refuses to hand you one that breaks the page limit. Nothing about fonts, margins, footers or citation numbering is your problem.

You getHow
A4, 16 mm margins, Times-metric font, 11 pt body, single spacing, page footerEncoded once in _quarto.yml + tex/msca-header.tex
A hard formatting gatescripts/check_msca_compliance.py — measures the rendered PDF against every MSCA rule (A4, Times fonts, 11 pt, 15 mm, footer, page cap, leftover placeholders). The build fails on any of them.
Compact numbered citations from a BibTeX libraryreferences.bib + nature.csl
Live preview while writingscripts/preview.sh — hot-reloading HTML
Word export for supervisor commentspixi run proof
A reproducible toolchainpixi.toml + pixi.lock, or the Docker image

Where these rules come from: the official MSCA Application form (V5.0, 27.03.2026), section 3.4 "Page limit and formatting". It is reissued each call — re-check it against a new form before reusing this scaffold. Two details worth knowing: the body font is TeX Gyre Termes, which is metric-compatible with Times New Roman and accepted by MSCA under its other name Nimbus Roman No. 9 L (that is the answer if anyone asks why the form says "Times New Roman" and pdffonts says TeXGyreTermes); and captions, footnotes and the footer may be smaller than the body but never below 8 pt — the footer is set at 9 pt and captions at 10 pt, legal only because of that floor.

Before you write a word
Read WRITING_METHOD.md first (pixi run method renders it). It carries the per-section blueprint, the evaluator scoring rubric to self-assess against, the craft rules distilled from two funded example proposals, and a ranked register of what is currently wrong with this draft. This manual only tells you how to operate the machine.

Two ways to get the toolchain. Pick one:

Route A — Pixi recommended for writing
Native install, fast renders (~12 s), live preview works, VS Code integration works. This is what you want day to day. Go to §2.
Route B — Docker for frozen, offline, or rescue builds
A ~3.5 GB image with the whole LaTeX distribution baked in. Renders identically on any machine, in any year, with no network. Slower, and less pleasant to write in. Go to §3.

2Set up a clean laptop (Route A)

Roughly 20 minutes, most of it waiting on downloads. macOS shown; Linux is identical, Windows works the same via PowerShell.

1
Install VS Code — code.visualstudio.com. Then install the two extensions this scaffold expects; VS Code will offer them automatically because they are listed in .vscode/extensions.json. 
# Quarto language support, and an offline grammar checker
code --install-extension quarto.quarto
code --install-extension ltex-plus.vscode-ltex-plus
2
Install Pixi, which manages every other tool. 
curl -fsSL https://pixi.sh/install.sh | bash
Close the Terminal and open a new one so the PATH change takes effect. Check it worked: pixi --version.
3
Get the project folder. If it is in git, clone it. Otherwise copy the folder across — but exclude .pixi/, which is a machine-specific 700 MB environment that will be rebuilt. 
git clone <repo-url> MSCA
cd MSCA/work
4
Build the environment and the LaTeX engine. Run both, in this order, from the folder containing pixi.toml. 
pixi install       # Quarto, Python, poppler — exact versions from pixi.lock
pixi run setup     # TinyTeX, a self-contained LaTeX distribution
The first render then pulls any missing LaTeX packages from CTAN automatically. That needs a network connection once.
5
Prove it works. 
pixi run build
Success looks like this — every part rendered, then every PDF measured: 
Output created: _build/partB1.pdf

MSCA formatting compliance — _build/partB1.pdf
  [PASS] A4 page size            all 9 pages 595x842pt
  [PASS] Times fonts, embedded   5 font(s), all embedded: TeXGyreTermes-…
  [PASS] Font size >= 11 pt      histogram: 8.0pt:81ch, 9.0pt:180ch, …
  [PASS] Margins >= 15 mm        top 16.6mm, right 15.3mm, bottom 16.8mm, left 15.8mm
  [PASS] Footer 'Part B - Page X of Y'  correct on all 9 pages
  [PASS] Page limit              9/10 pages, 1 page(s) to spare
COMPLIANT: all 7 hard checks passed.
If any line says FAIL, the command exits non-zero and the PDF must not be submitted.
Open the right folder
In VS Code, open MSCA/work — the folder that contains pixi.toml — not the parent MSCA folder. Every pixi run command fails from the parent with could not find pixi.toml, and the Quarto extension will not recognise the project. If you also want the reference PDFs visible, use File → Add Folder to Workspace to add the parent as a second root.

3The Docker route

Route A depends on TinyTeX fetching LaTeX packages from the internet on first use. That step is networked and mutable, so it is the one part that can drift between machines or fail years later. The Docker image freezes it.

Use Docker when: you need a build that is guaranteed reproducible for archival or resubmission; you have no network; your local TeX install has broken; or you are rendering in CI.

amd64 only — not a preference
conda-forge publishes no quarto build for ARM Linux, so the environment cannot be solved on linux-aarch64. The image is therefore amd64, and on an Apple Silicon Mac it runs under emulation — slower, but identical for everyone. --platform linux/amd64 is required in every command.
# build once, from the folder holding pixi.toml (~10 min)
docker build --platform linux/amd64 -t msca:latest .

# render Part B-1 — outputs land in _build/ on your real disk
docker run --rm --platform linux/amd64 -v "$PWD:/work" msca:latest

# prove it needs no network at all
docker run --rm --platform linux/amd64 --network none -v "$PWD:/work" msca:latest

# any other command works too
docker run --rm --platform linux/amd64 -v "$PWD:/work" msca:latest quarto render partB2.qmd
docker run --rm --platform linux/amd64 -v "$PWD:/work" msca:latest pdffonts _build/partB1.pdf

# live preview, then open http://localhost:4200/partB1.html
docker run --rm --platform linux/amd64 -p 4200:4200 -v "$PWD:/work" msca:latest \
  quarto preview partB1.qmd --to html --port 4200 --host 0.0.0.0 --no-browser

# poke around inside
docker run --rm -it --platform linux/amd64 -v "$PWD:/work" --entrypoint bash msca:latest
Verified
On 3 August 2026 this image rendered the real Part B-1 with --network none to 9/10 pages, with all four TeX Gyre Termes faces embedded — byte-for-byte the same result as the native build.

The image deliberately does not run pixi at render time. The project folder you mount carries its own .pixi/ built for macOS, and using it inside a Linux container fails on platform mismatch. The image puts its own solved environment on PATH instead, so the mounted one is ignored.

4Starting a new proposal from this scaffold

The machinery is funder-agnostic apart from three files. To reuse it:

1
Copy the folder, dropping the generated and project-specific parts: 
cp -R MSCA/work ~/Documents/NEW-PROPOSAL
cd ~/Documents/NEW-PROPOSAL
rm -rf .pixi _build .quarto .git WRITING_METHOD.* review why_inputs partB1_excimp_files
rm -f  sections/*.qmd references.bib CLAUDE.md partB2.qmd partB1_excimp.qmd
2
Adjust the three things that encode this funder's rules:
FileChange
scripts/check_all.shThe single list of which PDFs exist and what limit each carries — pixi.toml, Makefile and Dockerfile all call this one script, so a changed cap is a one-line edit here. The rules themselves (A4, Times, 11 pt, 15 mm) are constants at the top of scripts/check_msca_compliance.py.
tex/msca-header.texFont, margins and the Part B - Page X of Y footer text
_quarto.ymlMargins (geometry:), font size, and the citation style (csl:)
3
Create your own section files under sections/, list them in partB1.qmd with include directives, then git init and pixi install.
Citation styles
nature.csl gives compact superscript numerals, which saves a lot of space. Thousands of other styles are at zotero.org/styles — download one, drop it in the folder, point csl: at it.

5The daily writing loop

This is the answer to "I opened the file, now how do I see my changes?"

1
Open the project. code ~/Documents/MSCA/work — again, the work folder, not its parent.
2
Start the live preview once, in the VS Code terminal (Ctrl+`), and leave it running all session: 
pixi run preview
It serves http://localhost:4200/partB1.html. The port is fixed, so the URL never changes.
3
Put the preview beside your text. Either open that URL in a browser on a second monitor, or keep it inside VS Code: Cmd+Shift+P → Simple Browser: Show → paste the URL. Drag the tab to the right half of the window.
4
Edit sections/_excellence.qmd (or whichever section) and hit Cmd+S. The preview rebuilds in about four seconds and refreshes itself.
5
Check the real page count every few paragraphs: 
pixi run build
This is the command that governs the document — it is the only build that has been checked. Keep _build/partB1.pdf open in Preview.app and it refreshes on its own each time you rebuild.
The preview shows prose, not pages
The live preview is HTML. It shows wording, structure and flow — it cannot show you pagination, because HTML has no pages. Only pixi run build tells you whether you are over the limit — or whether anything else about the formatting has drifted. Never judge "did that edit fit?" from the preview.
Why a script instead of plain quarto preview
Two Quarto behaviours, both verified on 3 August 2026 with Quarto 1.9.38:
  1. quarto preview watches only the file you name. Files pulled in with {{< include >}} are not watched — so editing a sections/*.qmd file would leave the preview silently stale, showing old text with no error. scripts/preview.sh nudges the master file when a section changes.
  2. quarto preview pointed at PDF renders once and then fails on every subsequent rebuild. The live loop therefore runs on HTML, which reloads cleanly every time.

6Which file holds what

You only ever edit the content files. Everything else is machinery.

FileWhat is in it
sections/_excellence.qmdSection 1 — Excellence. Part B-1.
sections/_impact.qmdSection 2 — Impact. Part B-1.
sections/_implementation.qmdSection 3 — Implementation (work plan, Gantt, risk table). Part B-1.
partB2.qmdPart B-2 — CV, host capacity, ethics, AI declaration. No page limit.
references.bibThe reference library. Cite entries with [@key].
partB1.qmdThe master file that stitches the three sections together. You rarely touch it.
WRITING_METHOD.mdThe per-section blueprint, evaluator rubric and craft rules. pixi run method renders it to a readable page.
_build/All rendered output. Generated — never edit, and never store anything here.
review/Annotated files coming back from your supervisor. Kept out of _build/ on purpose.
Never keep anything in _build/
pixi run clean is rm -rf _build .quarto. A supervisor's commented Word file left in there is one command away from gone. Put incoming files in review/.

7Formatting cheat-sheet

You writeYou get
**bold text**bold text — for the lines a busy reviewer skims
*italic text*italic text — species names, emphasis
## HeadingA sub-section heading (## = level 2, ### = level 3)
- itemA bullet point (dash, then a space)
[@niemiec2017]A citation — renders as a superscript number and joins the reference list
[@a2020; @b2021]Two citations at once
<!-- a note -->A hidden comment. Does not appear in the PDF.
| A | B |A table row. Keep the |---|---| divider under the header row.
Blank lines matter
Leave one empty line between paragraphs. A heading, a bullet list, or a table each need a blank line before and after them, or they will not render as you expect.
Unbalanced ** is the silent one
An opening ** without its closing pair prints literal asterisks into the finished PDF, and nothing warns you. This has already happened twice in this project. Check before submitting: 
grep -n '\*\*' sections/*.qmd partB2.qmd | awk -F: '{n=gsub(/\*\*/,"",$0); if (n%2) print}'
Any line it prints has an odd number of markers and needs fixing.

8Adding a reference

1
Paste a BibTeX entry at the end of references.bib: 
@article{smith2024,
  author  = {Smith, Jane and Doe, John},
  title   = {A very important paper about neutrophils},
  journal = {Nature},
  year    = {2024},
  volume  = {600},
  pages   = {123--130},
  doi     = {10.1038/s41586-024-00000-0}
}
The word right after { — here smith2024 — is the key.
2
Cite it in the text: …as recently shown [@smith2024]. Save and render; it appears with the right number.
Rule
Only cite keys that exist in references.bib. A missing key renders as a broken ? in the PDF. Never invent a DOI — omit the line if you do not have one. Which keys are allowed at all, and what evidence a claim needs before it can be cited, is CLAUDE.md § Claim guardrails.

All commands run from the folder containing pixi.toml.

Prefer make? make setup, make build, make pdf, make preview, make b2, make all, make check, make hooks and make clean all exist. They do not go through Pixi — the Makefile calls quarto and python straight off your PATH, so this route only works if you already have Quarto, a TeX engine and PyMuPDF installed. There are no make equivalents of proof, docx or method.

Word is for feedback only
The .docx carries the full text, headings, tables, numbered citations and reference list, so a supervisor can comment. But it drops the layout — A4, margins, the Times font, the footer, the pagination — and Word does not enforce the page limit. Always submit the PDF, and re-check the page count after folding in any edits.

10The page limit

Critical
Part B-1 must be 10 pages or fewer. The submission system makes everything past page 10 invisible to evaluators — an overflow does not error, it silently deletes your Implementation tables. The build guards this: pixi run build prints the count and fails if you exceed it.

If an edit pushes you over, shorten the new text or trim elsewhere, then re-render until it fits. Two things to know about how the pages move:

  • Page breaks jump in whole lines, because tables become longtables that cannot split gracefully. Never judge a trim by "it looks shorter" — judge it by the number the build prints.
  • The numeric citation style is already on (nature.csl, via the csl: line in _quarto.yml) — that lever is spent. The remaining levers are structural, not verbal: trim the reference list, convert a table to prose, or drop 1 mm of margin. The measured cut order is WRITING_METHOD.md device C24.

11Spelling & grammar

In the editor — LTeX

Grammarly's desktop app cannot attach to VS Code; do not spend time trying. The in-editor equivalent is LTeX+, which is offline and understands Markdown and LaTeX, so it will not flag [@smith2024] or \usepackage as misspellings. It is already configured in .vscode/settings.json, including a dictionary of the project's technical terms; add your own words there as they come up.

For a thorough pass — Grammarly via Word

1
pixi run proof — renders _build/partB1.docx and opens it.
2
Review Grammarly's suggestions in Word, with the add-in.
3
Apply each fix you accept by hand, in the .qmd, one at a time. Then re-render and confirm the page count has not moved.
Never paste the Word text back over the .qmd
The round-trip has already converted [@key] into plain superscript numerals and flattened the tables. Pasting it back destroys every citation silently — they will look fine until you rebuild and the reference list is empty.
Suggestions to refuse
Set Grammarly to British English · Formal · Academic · Expert · Neutral — never "Confident" or "Engaging". Reject anything that removes a calibrated hedge: deleting one upgrades a claim above the evidence behind it, which is the most damaging edit available in a proposal. Also refuse changes inside tables, and hyphens replacing en-dashes in ranges such as 2018–2023 or WP1–WP3. The full seven-row reject list with reasons is WRITING_METHOD.md §A.4; the protected hedge strings themselves are in CLAUDE.md § Claim guardrails. Do not retype either list here.

12Version control & undo

The project is a git repository. Use it instead of copying files to backups/ by hand — that habit produced 57 stray .bak files under backups/ before it was retired — every one preserved in the first commit, so nothing was lost.

# before a risky edit
git add -A && git commit -m "before rewriting 1.2"

# see exactly what you changed since the last commit
git diff

# throw away changes to one file
git checkout -- sections/_excellence.qmd

# browse history
git log --oneline

The .gitignore keeps the repository small — around 1 MB — by excluding _build/, .pixi/, .quarto/ and the literature PDFs. Those are all either regenerable or too large to version.

13Never touch these

Leave alone
_quarto.yml, the tex/ folder, nature.csl, and everything in scripts/. These enforce compliance — page size, margins, font, footer, citation numbering, and the gate that measures all of it. Editing them can break the rules silently. One trap in particular: every .qmd that becomes a PDF must be listed under project.render in _quarto.yml. A file left off that list is rendered standalone, without the format block, and comes out US Letter in Latin Modern with no footer — see lessons.md. In particular: do not add a cover page or a table of contents, and never shrink table text below the body size.

The knobs you may turn

The rules above come from the official Application form (V5.0, 27.03.2026), §3.4. Four things inside them are genuinely adjustable:

KnobWhereNote
Marginsgeometry: in _quarto.ymlCurrently 16 mm. The MSCA minimum is 15 mm — measured on the built PDF as left 15.9 / right 15.2 / top 16.2 / bottom 15.2 mm, so the 1 mm buffer is real. Drop to 15 mm for maximum writing space.
Citation stylecsl: in _quarto.ymlAlready numeric via nature.csl. Superscript numerals are far more compact than author–date; swap for any style from zotero.org/styles.
Footer "of Y"tex/msca-header.texPrints the real page total. To print "of 10" instead, replace \pageref{LastPage} with 10 — see the one-line note in the file.
TeX enginepdf-engine: in _quarto.ymlDefault pdflatex + tgtermes. Also compiles with xelatex/lualatex (add mainfont: "TeX Gyre Termes", which gets you effortless Unicode and makes the mapping block in the header unnecessary), or tectonic if you want a self-fetching engine.
